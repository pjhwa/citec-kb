## 2. 항목별 상세

### 1. 평가 게이트에 지연 회귀 판정 추가
- **배경:** `compare`는 recall 하락·통과→실패만 판정한다. 이번에 B1 동의어가 만든 지연 회귀(probe-2 2.4s→24.3s, 운영 `Linux OOM 점검 방법` 검색 34~38s)가 게이트를 통과해 운영에 나갔고, 사용자가 `kb_ask` 지연을 보고서야 발견됐다.
- **내용:** 케이스별 `latency_ms`를 비교해 (a) 동일 케이스 지연이 N배·M초 이상 늘면 경고/실패, (b) 군별 p50/p95 임계 비교. dev 지연은 절대값이 의미 없으므로 **같은 환경 전/후 상대 비교**만 사용.
- **이득:** 같은 종류의 회귀를 배포 전에 차단. **리스크:** 노이즈로 오탐 가능 → 임계는 넉넉히(예: 3배 and +5초). **비용:** 하네스 수정 + 테스트.

### 2. 스킬 갱신

### 3. Fabrix 운영 안정화
- **미확인 사항:** 호출 한도(분당/일), 필터 **차단**(`FR-3xx` 등) 시 응답 형식(현재는 `JAILBREAK ... warned`만 관측, 빈 `content`로 폴백), `llmConfig`의 추론 제어 필드(문서에 `anyOf {}`로만 표기), 모델 교체(`gpt-oss-120b(Low)`, `Gemma4` 등이 더 빠르다고 표시되나 `[C#]` 인용 준수 품질은 미검증).
- **관측:** 추론 약 3s + 답변 1.4s, `/v1/chat` 24s 중 검색이 약 9.5s. 즉 생성보다 검색이 큰 비중.
- **작업:** (a) Fabrix 담당 문의, (b) 차단·한도 오류의 사유 문구를 `llm_error`로 노출(이미 `errorCode`/`detailMessage`는 노출), (c) 모델 후보 3종으로 같은 질문 20개를 돌려 `generation_status`·인용 정합성·지연 비교, (d) 필요 시 재시도(429 한정)·타임아웃 조정.
- **리스크:** 한도를 모르는 상태에서 호출이 늘면 쿼터 소진(현재는 재시도 없음, `kb_ask`당 최대 3회 호출). **비용:** 문의 대기 시간이 지배적.

### 4. 제목 ILIKE 스캔 제거 / `pg_trgm` 인덱스
- **배경:** `search.py`의 `like_terms` 경로는 `title/header_context/external_id`에 대해 `ILIKE '%…%'`를 수행(순차 스캔, dev 약 0.6s/회), multi-query가 부질의마다 반복. 이번 두 번의 회귀(B3, B1)가 모두 이 경로에서 났다.
- **옵션:** (a) 해당 경로 제거 후 홀드아웃·평가셋으로 영향 측정, (b) `pg_trgm` GIN 인덱스(`documents.title`, `chunks.header_context`) 추가.
- **이득:** 검색 기본 지연 대폭 감소 가능(운영 단일 질의 약 10s). **리스크:** (a) 제목 일치 가산이 사라져 순위 변화 → 게이트 필수, (b) 인덱스 크기·생성 시간·운영 마이그레이션 승인. **비용:** (a) 작음, (b) 중간.

### 5. inode 류 질의 (multi_query 병합 방식)
- **원인(확정):** 단일 질의 경로에서는 `PISAOLNX_04.04.03`이 4위였으나, multi-query가 부질의별 점수를 max로 합치고 범용 헤드(`파일 시스템`)가 만든 점수가 앞서 REST 최종 순위는 8위. B1~B4로는 풀리지 않음.
- **옵션:** 부질의 점수를 순위 기반(RRF)으로 합치거나, 원 질의 상위 k에 든 문서에 합의 가산. **리스크:** 병합 변경은 모든 질의 순위에 영향 → 홀드아웃·평가셋 전수 게이트, 최악의 경우 recall 하락. **이득:** 질의 유형 일부(체크리스트 + 일반어 헤드). 스킬 우회(`kb_list_checkitems`)로 당장은 우회 가능하므로 서두를 이유는 작다.

## 3. 이번 작업에서 얻은 운영 교훈
1. 검색 경로에 **새 변형/쿼리**를 추가할 때는 항상 ILIKE·순차 스캔 경로를 타는지 확인한다 (이번에 두 번 발생).

3. `up -d api`는 `.env` 변경에, `restart`는 코드 변경에. 임시 스크립트를 운영 저장소 안에 두면 배포 스크립트가 중단된다 (`x.py`).
4. Fabrix는 추론 토큰이 `max_new_tokens`를 같이 쓰므로 한도를 낮게 주면 빈 응답이 온다 (`FABRIX_THINK_HEADROOM`).
