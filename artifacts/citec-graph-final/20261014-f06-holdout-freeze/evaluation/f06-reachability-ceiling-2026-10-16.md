# F06(R05) 도달 가능성 상한 측정 및 보류 결정 — 2026-10-16

## 배경

`cost-target-decision-2026-10-15.md`에서 비용 상한(검색 대비 2배)과 품질 목표(비열화 금지)를
정한 뒤, 실제 랭킹/후보 결합 설계(브레인스토밍)를 진행하던 중 "그래프가 애초에 정답에
도달 가능한가"를 먼저 확인해야 한다는 지적에 따라 측정했다.

## 측정 방법 (읽기 전용, Neo4j 직접 Cypher)

naive 비교군 B에서 `found_by_neither`로 분류된 17건(30건 중, 검색도 그래프도 못 찾은 케이스)
각각에 대해:

1. top-5 검색 앵커 각각과 정답 후보(`candidate_documents[].document_id`) 사이의 **1-hop 직접
   연결**을 확인.
2. **2-hop 경로**(중간 노드 레이블 무관)를 전부 수집하고, 중간 노드가 `Component`일 경우
   `HAS_COMPONENT` 입력 degree와 `is_hub`(`neo4j_client.py:90`, 임계값 5000) 여부를 기록.
3. 2-hop에도 전혀 경로가 없던 2건(performance-01/02)은 **3-hop**까지 확장해 재확인.
4. 17건 전체에서 2-hop 중간 노드의 **레이블 종류**를 전수 조사(Component 외 다른 신호 경로가
   있는지 확인).

## 결과

| 항목 | 결과 |
|---|---|
| 1-hop 직접 연결 | **0/17** |
| hub 안 거치는(비-hub) 2-hop 경로 | **2/17** — network-11(중간 "L2/L3", degree 670, 5번째 앵커를 통해서만), storage-02(중간 "NetApp", degree 4412, 2번째 앵커를 통해) |
| hub(degree ≥ 5000)를 거쳐야 도달 | 15/17 — degree 7,785 ~ 43,187 (최대 임계값의 8배 이상) |
| 2-hop 중간 노드 레이블 종류(17건 전체) | **`Component`뿐** — FailureBucket/Document 매개 경로 0건 |
| performance-01 3-hop 확장 | 경로 1개 발견, 그마저 degree 29,275 hub 경유 — 신호 없음 |
| performance-02 3-hop 확장 | 경로 없음 |

**주의**: storage-02는 이전 비교군 B 측정에서 이미 "정답 document_id가 홀드아웃 고정값과
다른 것 같다"는 ground-truth 의심이 제기된 건이라, 사실상 신뢰할 수 있는 비-hub 구제는
**network-11 1건뿐**이다.

## 결론

- 이 그래프 구조에서 문서 간 "다리" 역할은 거의 전적으로 `Component`(장비/기술 태그)가
  수행하고, FailureBucket 공유나 Document 직접 관계 같은 다른 신호는 이 17건 미스
  케이스에는 존재하지 않는다. 범위(3-hop, 다른 레이블)를 넓혀도 추가로 건질 게 없음을
  확인했다.
- hub를 거쳐야 도달하는 15/17건은 degree가 임계값(5000)보다 1.5~8.6배 커서, 거리/관계
  가중치를 아무리 잘 설계해도(`1/log(degree)` 류 감쇠 포함) 수만 개 문서 중 하나를
  구분해내는 신호가 되지 못한다 — 이미 운영 코드의 `is_hub` 필터가 정확히 이걸 걸러내고
  있었고, 그래서 naive 비교군 B가 recall/MRR 개선 0건이었다.
- 신뢰할 수 있는 구제 가능 건수는 **30건 중 최대 1건(network-11)** — recall@10을
  43.3% → 46.7%로 올리는 수준. 투자(랭킹 로직 설계·구현·유지보수) 대비 효과가 낮다고
  판단해, **F06(R05) 설계를 일시 보류**하기로 결정(2026-10-16, 사용자 결정).

## 보류 중 남겨둔 설계 결론 (재개 시 참고)

브레인스토밍 중 이미 합의됐던 사항들 — 재개 시 처음부터 다시 묻지 않아도 됨:
- 진입점: `/v1/search` 확장, `question_context: {"question": "..."}` 필드 추가(호환성 유지).
- 앵커 후보: 고정 top-N(N=5로 시작).
- hub 필터: 앵커가 아니라 **중간(bridge) 노드**의 degree 기준(이미 `explore()`에
  `is_hub`로 존재 — 이번 작업은 새 필터가 아니라 기존 임계값/가중치 조정이었음을 확인).
- 관계 유형 가중치 + hop 거리로 점수화(구조는 합의, 구체 가중치는 미정).
- 최종 랭킹: 재정렬(rerank)이되 승격 상한 있음 — **그래프 신호로는 top-10 "진입"만 허용**,
  이미 top-10 안의 순서 교환은 불허(비열화 방지).
- 그래프로 새로 들어온 후보끼리 정렬: 앵커의 원 검색 순위(1차 키) + 관계가중치/hop(2차 키).
- 앵커별 타임아웃(고정값, 예: 3초) + 전체 예산(검색 대비 2배) 초과 시 중단 + `partial: true`.
- 그래프 확장은 페이지 1(top-10)에만 적용, 2페이지 이후는 순수 검색 결과.
- `total_count`: 그래프 확장 미적용 시 기존 방식 유지, partial이면 unknown, 완료 시 estimated.
- 동점 타이브레이커: 문서 ID 사전순(제안했으나 최종 확인 전 보류 결정으로 미확정).

재개 조건: (a) 그래프에 Component 외 다른 저밀도 매개 신호가 새로 생기거나(스키마 확장),
(b) 홀드아웃 외 더 큰 샘플에서 비-hub 구제율이 유의미하게 높게 나오거나, (c) 비용/정확도
목표가 완화되는 경우 재검토.
