# 조회 경로 계층 리팩토링 실행 프롬프트

이 파일을 프롬프트로 받은 것이면, 그 즉시 아래 절차를 실행한다. 설계를 다시 쓰지 않는다. 범위 밖의 개선을 제안하고 멈추지 않는다.

사용자가 이 파일 경로만 알려 주고 “실행하라”고 해도 같다. 파일 전체를 읽고 1단계부터 한다.

한 줄로 시킬 때 사용자는 이렇게만 보내면 된다.

```text
docs/design/query-path-layer-refactor-PROMPT.md 를 읽고 그대로 실행하라.
```

## 이미 결정되어 있어 묻지 않는 것

아래는 사용자에게 다시 묻지 않는다. 답변이 설계를 뒤집으라고 명시하기 전에는 지킨다.

- 동작 보존 이동이다. 함수 본문은 잘라 붙인다. 랭킹 수식, 동의어 3소스, `SEARCH_*` 기본값, Alembic, nginx, 워커, `packages/domain`은 건드리지 않는다.
- 순서는 PR1, PR2, PR3, PR4, PR5, PR6, PR7, PR8, PR9이다. 한 세션에서는 병렬로 나누지 않는다. PR2 다음 PR3이다. PR5 다음 PR6이다. PR7 다음 PR8이다. PR4의 allowlist 수정은 기존 리터럴을 갈아끼우지 않고 단언을 추가한다.
- 라우터 재수출과 호출 시점 인자 주입은 유지한다. `extract_lexicon_components`와 `_BUILD_SHA_FILE`은 서비스 기본 인자에 바인딩하지 않는다.
- `HTTPException`을 도메인 예외로 바꾸는 곳은 `graph_explore`의 404 한 곳과 `get_checkitem`의 400/404뿐이다. `_map_section`과 업로드 헬퍼는 `HTTPException`과 `detail`을 본문에 둔다.
- 보안 통제는 본문과 함께 이동한다. 없는 `Depends(require_roles...)`를 추가하지 않고, 있는 admin 게이트 여섯 개를 빼지 않는다. `attach_document_access`, `document_access`, `filter_excluded_documents`, `apply_exposure_policy`, `Path.name`, 마스킹 미들웨어, `_headers`의 토큰을 이동 중에 강화하거나 빼지 않는다.
- 설계의 잔여 위험 7항은 이 9개 변경 안에 넣지 않는다. 고치라는 답이 있어도 9개가 끝난 다음의 별도 변경이다.
- 개발용 compose Neo4j 볼륨 `neo4jdata`에는 테스트 URI를 꽂지 않는다.
- 배포, 프로세스 재시작, force push, 설정 변경, 설계 문서나 이 프롬프트 파일을 리팩토링 커밋에 넣는 일은 하지 않는다.
- `test_external_compat.py`의 기대 문자열을 바꾸지 않는다. `map_sync.py`, `explore.py`, `identity.py`의 `app.routers` 주석을 지우지 않는다.

## 1단계. 읽기와 사전 확인

코드를 수정하기 전에 설계 문서의 스펙, PR Plan, 보안 절, 체크리스트를 읽는다. 이어서 저장소에서만 확인한다.

- `git status --short`, `git rev-parse --abbrev-ref HEAD`, `git rev-parse HEAD`
- 설계가 말하는 세 간선이 아직 있는지: `query/prevention.py`와 `query/planner.py`의 `app.routers.checkitems`, `confluence/map_space_setup.py`의 `app.routers.confluence_map`
- 이동 대상 심볼이 아직 그 파일에 있는지: `list_checkitems_core`, `get_checkitem`, `slugify`에 해당하는 `_slugify_space_key`, `build_fts_variants`, `graph_status`, `graph_explore`, `external_compat`의 위키·업로드 헬퍼, `mcp-server/server.py`의 포맷 함수와 `_headers`
- `.venv/bin/python` 존재, `docker ps`로 postgres 컨테이너 이름, `mcp` 임포트가 되는 인터프리터

줄 번호는 설계와 달라도 된다. 심볼, 인자, `detail` 문자열, 호출 이름이 다르면 불일치다. 불일치 목록을 만든 뒤 2단계로 간다. 이 단계에서는 파일을 고치지 않는다.

## 2단계. 사용자에게 묻고 답을 기다린다

2단계가 끝나기 전에는 파일을 만들거나 고치거나 커밋하지 않는다. 기본값을 답으로 가정하지 않는다. 질문 도구가 있으면 한 번에 묻고, 없으면 한 메시지에 아래 질문을 번호로 적어 답을 기다린다. 설계가 이미 닫은 항목을 보기로 넣지 않는다.

사전 확인에서 워킹트리가 깨끗하고 심볼이 설계와 맞으면 질문 A는 생략한다. 질문 B, C, D는 항상 묻는다.

### A. 진행을 막을 수 있는 저장소 상태

워킹트리에 이 작업과 무관한 변경이 있거나, 인용 심볼이 설계와 다르면 그것만 보여 주고 고른다.

1. 기존 변경은 그대로 두고, 그 위에 이 리팩토링만 추가한다.
2. 불일치 또는 기존 변경 때문에 중단한다. 차이를 보고만 하고 끝낸다.
3. 심볼이 어긋난 경우에만: 동작이 같은 이동으로 설계를 현재 코드에 맞춘다. 맞추기 전에 어긋난 심볼마다 현재 시그니처와 설계의 시그니처를 보여 준다. `detail`, 인증 게이트, SQL, 노출 필터가 다르면 이 보기를 고르더라도 그 차이는 다시 묻기 전에는 흡수하지 않는다.

권하는 답: 무관한 변경이 있으면 2. 줄 번호만 다르고 심볼이 같으면 A를 묻지 않고 진행한다.

### B. 잔여 보안 위험

설계 보안 절의 잔여 위험은 일곱 가지다. 게이트가 없는 읽기·업로드, `get_children`의 ACL 부재, `pg_missing`을 빼지 않는 노출 정책, `backend_error_reason`의 `str(exc)`, 업로드 `job.error`의 `str(exc)`, 백슬래시 파일명, 미확인인 마스킹 엔진 규칙.

1. 일곱 가지를 그대로 둔다. 9개 변경이 끝난 뒤에도 고치지 않는다. 권하는 답.
2. 9개 변경을 먼저 끝낸다. 그 다음 멈추고, 일곱 가지 중 어떤 것을 별도 커밋으로 고칠지 다시 묻는다. 그 수정은 동작이 바뀐다. 9개 커밋 안에 섞지 않는다.

### C. 검증 환경

체크리스트 15, 26의 DB 보강, 27은 환경이 없으면 yes가 될 수 없다. skip을 통과로 치지 않는다.

1. 그래프 통합은 사용자가 폐기 가능한 Neo4j URI와 `GRAPH_TEST_DATABASE_URL`을 이 답에 적었을 때만 실행한다. 안 적혀 있으면 15는 실행하지 못함이다. compose `neo4jdata`는 쓰지 않는다.
2. scratch DB는 `citec-kb-postgres-1`(또는 사용자가 적은 컨테이너)가 떠 있을 때만 `scripts/scratch_db_test.sh`로 돌린다. 없으면 해당 항목은 실행하지 못함이다. 컨테이너를 새로 띄우지 않는다.
3. MCP 테스트는 `mcp`가 임포트되는 인터프리터에서만 돌린다. 없으면 27은 실행하지 못함이다. 패키지를 설치하지 않는다.

권하는 답: URI와 인터프리터를 알고 있으면 적고, 모르면 비워 둔다. 비워 두어도 코드 변경 9개는 끝까지 한다.

### D. 기록 방식

1. 현재 HEAD에서 브랜치 `refactor/query-path-layer`를 만들고, 설계의 PR 제목 그대로 커밋 9개를 쌓는다. push 하지 않고 GitHub PR도 열지 않는다. 권하는 답.
2. 커밋하지 않는다. 워킹트리에만 둔다.
3. 1과 같되, push와 PR 생성까지 한다. 원격 이름과 베이스 브랜치를 답에 적게 한다. 적혀 있지 않으면 push 하지 않고 1로 되돌린다고 말한 뒤 코드를 진행한다.

답을 받기 전에는 브랜치를 만들지 않는다.

## 3단계. 구현

답 A가 중단이면 구현하지 않는다. 그 외에는 답대로 9개를 끝까지 한다.

각 PR마다 같은 순서를 반복한다.

1. 설계 문서에서 그 PR의 스펙 절만 다시 읽는다. 옮길 이름, 라우터에 남을 이름, 붙여 넣기 때 허용된 편집, 재수출, 테스트를 메모한다.
2. 현재 소스에서 그 이름의 본문을 확인한다. 본문이 읽는 이름이 스펙 목록에 없으면 멈추고 그 PR만 보류한 채 사용자에게 누락 심볼을 보여 준다. 목록에 없는 헬퍼를 새로 쪼개지 않는다.
3. 본문을 옮긴다. 값, SQL, 정규식, 로그 형식 문자열, `detail`은 다시 치지 않고 그대로 붙인다. 스펙이 허용한 편집만 한다. PR6의 편집은 셋뿐이다. `body.<field>`를 `command.<field>`로, 404 raise를 `raise GraphAnchorNotFound()`로, `extract_lexicon_components(...)` 호출 한 곳을 `extract_components(...)`로. `_drop_inactive_buckets = drop_inactive_buckets`를 서비스에 둔다.
4. 그 PR 스펙의 pytest를 실행한다. 실패하면 동작을 바꿔 맞추지 않는다. 이동이 호출 이름이나 import를 빠뜨린 것이면 스펙 범위 안에서 고치고 다시 돌린다. 두 번 고쳐도 실패하면 그 PR을 커밋하지 않고 멈추고, 실패 명령과 마지막 오류를 보고한다. 이후 PR은 시작하지 않는다.
5. 질문 D가 커밋을 허용하면 그 PR의 파일만 스테이징해서 커밋한다. 제목은 설계 PR Plan의 제목과 같다. 메시지 본문은 옮긴 심볼과 돌린 테스트 한 줄이다. 설계 문서, 이 프롬프트, 무관한 변경은 스테이징하지 않는다.

PR4에서 DB 테스트는 질문 C에 컨테이너가 있을 때만 돌린다. 없으면 커밋 본문에 `scratch DB 미실행`이라고 적는다. 단위 테스트가 실패했는데 DB 미실행을 이유로 넘어가지 않는다.

PR5와 PR6의 `tests/test_graph_router.py`는 질문 C에 URI가 있을 때만 돌린다. skip이 1이라도 있으면 그 체크 항목은 yes가 아니다. URI가 없으면 코드를 멈추지 않고, 커밋 본문에 `graph router 통합 미실행`이라고 적는다.

PR9는 `docker-compose.yml`의 mcp 볼륨과 `mcp-server/Dockerfile`의 `COPY server.py ask_fold.py formatters.py .`를 같은 커밋에 넣는다. `_headers`, `_client`, `@mcp.tool` 함수는 `server.py`에 둔다.

## 4단계. 중간에 다시 묻는 경우

다음이 아니면 진행 중에 “계속할까요”를 묻지 않는다.

- 질문 A의 3을 골랐는데 `detail`, 게이트, SQL, 노출 필터가 설계와 다르다.
- 옮긴 본문이 읽는 이름이 스펙의 닫힌 목록에 없다.
- 스펙이 허용한 편집만으로는 테스트가 실패하고, 실패를 없애려면 동작이 바뀐다.
- 질문 B가 2이고 9개 커밋이 끝났다. 그때 잔여 위험 일곱 가지를 하나씩 보여 주고, 고칠 번호만 받는다. 번호를 받기 전에 그 수정을 시작하지 않는다. 각 수정은 무엇이 바뀌어 클라이언트가 보게 되는지를 한 줄로 적고, 설계의 9개 커밋과 다른 커밋으로 분리한다.

질문 B가 1이면 4단계의 마지막 항목은 하지 않는다.

## 5단계. 체크리스트와 보고

9개가 끝나면 체크리스트 1–37을 설계 문서의 문장 그대로 검사한다. 소스 단언은 파일을 읽어 판정한다. 테스트 단언은 그 명령을 실행해 판정한다. 질문 C 때문에 실행하지 못한 항목은 yes로 적지 않는다.

보고는 이 순서로 한다.

1. 브랜치 이름, 커밋 9개의 해시와 제목. 커밋하지 않았으면 변경 파일 목록.
2. 사용자가 고른 A–D.
3. 체크리스트 표. 번호, yes 또는 no 또는 미실행, 근거가 된 명령이나 파일.
4. 미실행과 no가 있으면 그것을 완료의 빈칸으로 적는다.
5. 잔여 위험 7항은 이번 변경에 포함되지 않았다는 한 줄. 질문 B가 2이고 이어서 별도 커밋을 만들었다면 그 커밋만 따로 적는다.

배포와 재시작은 보고에 “하지 않았다”고만 적는다. 할지 묻지 않는다.
