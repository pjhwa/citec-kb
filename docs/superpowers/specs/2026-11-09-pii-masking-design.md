# 개인정보·고객 민감정보 마스킹 설계 (2026-11-09)

## 1. 목적과 범위

KB 데이터에 섞인 개인정보(사번, 주소, 전화번호, 이름)와 고객 민감정보(IP, 고객사명, 호스트명)를
**출력 시점**에 마스킹한다. DB 원본과 색인은 바꾸지 않는다. 권한 있는 사용자는 토글로 원본을 볼 수 있고,
원본 열람은 감사 로그에 남는다.

근거: 하위 문서 확인 결과 `Ⅹ. 기타 > [설문 및 수요조사]` 트리(confluence_map, 86건 중 본문 보유 76건)에
전화번호 17건, 주소 15건, 사번 관련 4건이 실제로 있다. 이름이 사번·주소·전화번호와 같은 줄/행에 함께 나온다.

### 이번 범위에서 하지 않는 것
- 적재 시점 마스킹 (원본 보존, 규칙 변경 시 재색인 불필요가 출력 시점 방식의 전제)
- 고객사 IP와 VDI IP 대역 구분 (둘 다 `net`)
- 벡터 임베딩에 들어간 원문 자체의 보호 (검색 결과 노출만 막는다)
- 에이전트가 `confluence-mcp.getPageByID`로 Confluence 원문을 직접 읽는 경로
- MCP를 통한 원본 보기

## 2. 분류와 롤별 가시성

| 분류 | 대상 | `viewer` | `author` | `senior`/`admin` |
|---|---|---|---|---|
| `pii` | 전화번호, 주소, 사번, 레코드 내 이름 | 마스킹 | 마스킹 | 토글 시 원본 |
| `net` | 모든 IP (IPv4/IPv6) | 마스킹 | 마스킹 | 토글 시 원본 |
| `biz` | 고객사명, 호스트명 | 마스킹 | 원본 | 원본 |

- `senior`/`admin`도 기본은 마스킹이다. `pii`/`net` 원본은 토글을 켠 요청에서만 나간다.
- `biz`는 기술지원·장애 관리에 필수라서 `author` 이상이면 토글 없이 원본이다.
- **`AUTH_MODE=off`**: 익명(현재 전 롤 보유)을 `author` 수준으로 취급한다. `pii`/`net`은 마스킹, `biz`는 원본.
  이 상태에서는 누구도 `pii`/`net` 원본을 볼 수 없다. 인증을 켜면 토큰 롤대로 전환된다.

## 3. 마스킹 엔진 — `apps/api/app/masking/`

순수 함수 `mask_text(text, level) -> (masked, hits)`. 요청·DB를 모르므로 미들웨어·CLI·테스트에서 재사용한다.

| 탐지기 | 규칙 |
|---|---|
| 전화번호 | `0\d{1,2}-\d{3,4}-\d{4}`, 하이픈 없는 `01\d{8,9}` |
| 주소 | 시·도로 시작해 시·군·구, 도로명(로·길), 번지, 건물, 동·호까지 이어지는 덩어리 전체 |
| 사번 | `사번` 라벨(`사번: 12345`) 또는 `사번` 열 헤더가 있는 표의 해당 열의 5자리 숫자만. 문서 전체의 5자리 숫자는 대상 아님 |
| 레코드 내 이름 | 같은 줄/표 행에서 위 탐지가 하나라도 걸리면 그 줄의 한글 이름 후보(2~4자, "프로" 등 직급 접미 포함) |
| IP | IPv4/IPv6 정규식 (`v1.2.3` 같은 버전 문자열 제외) |
| 고객사명·호스트명 | `config/masking_dictionary.json` 사전 + 호스트 명명 패턴 정규식 |

- **치환**: `[PHONE-1]`, `[ADDR-1]`, `[ID-1]`, `[NAME-1]`, `[IP-1]`, `[CUST-1]`, `[HOST-1]`. 번호는 한 응답 안에서 같은 값이면 같은 번호다. 응답 간에는 연결되지 않는다.
- **오탐 정책**: 애매하면 마스킹한다. 운영자가 `allowlist`(공개 DNS, 문서 예시 대역 등)로 예외를 둔다.
- **사전 파일**: `config/auth.json`처럼 mtime 변경 시 다음 요청부터 재로딩한다. 없거나 깨지면 `biz`만 비활성화하고 `pii`/`net`은 동작한다. 경고 로그를 남기고 `/v1/health`에 상태를 노출한다.

## 4. 미들웨어 — `MaskingMiddleware`

- `ApiAccessLogMiddleware` 옆에 추가. `/v1`, `/api` 아래 `application/json` 응답의 모든 문자열 값을 `mask_text`에 통과시킨다. 라우터는 수정하지 않는다.
- 제외: `/v1/health`, `/v1/ops/`, `/v1/auth/`, 스트리밍 응답.
- **Fail-closed**: 마스킹 중 예외 시 원본을 내보내지 않고 500. 응답 크기를 이유로 건너뛰지 않는다.
- 응답에 `masking` 필드 추가: `{"applied": true, "level": "...", "counts": {"pii": 3, "net": 1}, "unmask_denied": false}`.
- 내부 호출(워커 등)에도 예외 경로를 두지 않는다. 워커의 API 호출은 시드·작업 트리거(POST)뿐이다.

## 5. 원본 보기 토글

- 요청: `?unmask=1` 또는 `X-Citec-Unmask: 1`.
- `senior`/`admin`만 유효. 그 외가 요청하면 **403이 아니라 마스킹된 채로 응답**하고 `masking.unmask_denied: true`를 붙인다(UI 깨짐 방지). 이 요청도 감사 로그에 남긴다.
- 원본 응답은 감사 로그 기록이 성공해야만 내보낸다. 기록 실패 시 마스킹된 채로 응답한다.

## 6. 감사 로그 — `unmask_audit_log`

- 새 테이블(alembic 마이그레이션). 기존 `api_access_log`·`mcp_access_log`는 비동기 배치지만, 이 로그는 **원본 응답 전에 동기로 INSERT**한다(5절의 "기록 성공 후에만 원본" 보장을 위해). 원본 열람 요청에만 발생하므로 부하는 작다.
- 항목: 시각, 사용자 sub/name, 롤, 경로, 문서 ID, 마스킹 해제된 분류별 건수, 클라이언트 IP, 허용/거부.
- **값 자체는 저장하지 않는다. 보관 기간 정리 대상에서 제외(영구 보관).**

## 7. 웹 UI

- `auth.js`의 롤 정보로 `senior`/`admin`에게만 상단바(`nav.js`)에 "원본 보기" 토글을 표시한다.
- 상태는 `sessionStorage`. 탭을 닫으면 꺼진다. 켜면 모든 API 호출에 `X-Citec-Unmask: 1`을 붙인다.
- 켜진 동안 상단에 붉은 띠("원본 표시 중 · 열람이 기록됩니다").
- `[PHONE-1]` 같은 토큰은 회색 배지로 렌더링한다.
- `viewer`·`author`에게는 토글이 보이지 않는다.

## 8. MCP

- 마스킹이 API에서 끝나므로 `mcp-server` 코드는 거의 변경 없다. 공유 키(`author`)라 `pii`/`net`은 마스킹, `biz`는 원본이다.
- 원본 보기 파라미터를 열지 않는다.
- MCP 응답 머리에 한 줄 표시: `마스킹 적용: pii 3, net 1`.
- `kb_tools_help()`와 `docs/AI_AGENT_GUIDE.md`에 "`[PHONE-1]` 같은 토큰은 마스킹된 값이며 복원을 시도하지 말 것"을 추가한다.

## 9. 테스트

- **단위**: 탐지기별로 실제 형식을 합성한 가짜 값으로 검증. 일반 5자리 숫자, 금액, 버전 문자열이 마스킹되지 않는 오탐 방지 케이스 포함.
- **미들웨어**: 롤별 가시성 표 전체, `unmask_denied`, 예외 시 fail-closed, 감사 로그 기록·기록 실패 시 마스킹 유지.
- **회귀 방지**: `/v1`의 모든 GET 라우트를 순회해 JSON 응답이 미들웨어를 거치는지 확인(새 라우터의 우회 방지).
- **실데이터 점검 스크립트** (`scripts/`): 설문 트리 문서를 `viewer`로 조회해 분류별 건수만 출력한다. 실제 값은 출력하지 않는다.

## 10. 열린 항목

- VDI IP 대역 정보가 주어지면 `net`을 `net_vdi`/`net_customer`로 분리할 수 있다.
- 호스트명 명명 패턴과 고객사 사전의 초기 내용은 운영자가 제공해야 한다.
- 지번주소(번지만 있는 형식)의 탐지 누락률은 실데이터 점검 후 보정한다.
